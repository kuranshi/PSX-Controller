# PSX Controller

UNO R4 双 PS2 摇杆、A/B/X/Y 四个按键与 SSD1306 128×64 I²C OLED 状态显示。当前通过串口和 OLED 验证输入，尚未实现电脑 USB 游戏手柄映射。

## 程序文件

所有代码位于 `Test/sketch_nov2a/`：

- `sketch_nov2a.ino`：主程序、双摇杆采集、中心校准、灵敏度和串口输出。
- `Buttons.h`：四按键接口。
- `Buttons.cpp`：按键引脚、电平设置和独立消抖。
- `ControllerDisplay.h/.cpp`：OLED 状态快照接口、图形绘制、地址探测和分块传输。

所有源文件共同编译成一个固件，只上传一次。不要单独编译或上传 `.cpp`，也不要手动 `#include` 任意 `.cpp` 文件。

## 接线

仓库中的 `ABX00087-full-pinout.pdf` 是 UNO R4 WiFi 开发板引脚图，不是按键模块电路图。

| 输入 | 开发板引脚 |
| --- | --- |
| 摇杆 1 X / Y / SW（L3） | A2 / A1 / D2 |
| 摇杆 2 X / Y / SW（R3） | A3 / A0 / D3 |
| 按键 A | D4 |
| 按键 B | D5 |
| 按键 X | D6 |
| 按键 Y | D7 |
| OLED SDA / SCL | A4 / A5 |

注意：这是新的接线。请将原来的 L3 从 A0 移到 D2、R3 从 A5 移到 D3、摇杆 2 的 Y 从 A4 移到 A0，再连接 OLED。A4/A5 不再接任何摇杆信号。

两个摇杆 VCC 接 5V，GND 接开发板 GND。四个独立按键各有一端接指定 D 引脚，另一端接 GND，使用内部上拉，按下为 LOW。四脚轻触开关应连接按下时才导通的两组触点。

L3/R3 同样使用内部上拉，按下时接 GND；六个按压开关均独立消抖。OLED 的 GND 与开发板共地，VCC 按模块标注的额定电压连接，并按模块的 SDA/SCL 丝印接线，不按排针位置猜测。

若使用按键模块：S 接指定引脚，GND 共地，VCC 按模块要求供电。默认按下输出 LOW；高电平有效的模块需将 `Buttons.cpp` 的 `ACTIVE_LOW` 改为 `false`，且模块必须提供稳定的松开电平。

按键每 5ms 读取一次，按下或松开连续稳定 20ms 后更新，允许四键同时按下，不阻塞摇杆采集。

## Arduino IDE 编译与烧录

1. 打开 `Test/sketch_nov2a/sketch_nov2a.ino`。确认同目录有 `Buttons.h/.cpp` 与 `ControllerDisplay.h/.cpp`，IDE 中会显示对应标签页。
2. 在开发板管理器中安装 **Arduino UNO R4 Boards**（已安装则跳过）。在库管理器中安装 **Adafruit SSD1306**，弹出依赖提示时选择全部安装，包括 **Adafruit GFX Library**、**Adafruit BusIO**。本次编译验证使用的版本分别为 2.5.17、1.13.0、1.17.4。
3. 用 USB 数据线连接开发板。在 **工具 -> 开发板 -> Arduino UNO R4 Boards** 选择 **Arduino UNO R4 WiFi**；如果实际使用 Minima，改选 Minima。
4. 在 **工具 -> 端口** 中选择开发板对应的 COM 口。
5. 点击左上角 **验证（勾号）** 编译整个项目。
6. 关闭 VOFA、串口监视器和其他占用该 COM 口的软件，然后点击 **上传（右箭头）**。上电、上传后复位时松开两个摇杆，以便校准中心。
7. 上传完成后打开 VOFA，选择同一 COM 口、**115200** 和 **FireWater** 协议，再连接。串口监视器与 VOFA 不要同时占用同一个端口。

## OLED 显示

支持四针 I²C **SSD1306 128×64**，不适用于 SH1106 或 128×32 驱动配置。上半部左右为 `LEFT`、`RIGHT` 摇杆位置框与 X/Y 处理值，回中为 0，范围 -1000～1000；圆点随轴值变化，正 X 向右、正 Y 向下。方向不符合安装方式时，修改主程序的 `J1/J2_INVERT_X/Y`。

下半部显示 A/B/X/Y 与 L3/R3，按住时标签反白，松开后恢复，支持多个标签同时反白。显示的是采样后、消抖后的当前状态，短于显示周期的点击可能不会出现在屏幕上。

`ControllerDisplay.cpp` 顶部集中配置：

- `OLED_ADDRESSES`：按顺序探测 7 位地址 `0x3C`、`0x3D`；如模块另设地址，可修改此数组。不要填左移后的 `0x78`、`0x7A`。
- `OLED_ROTATION`：默认 `2`，画面旋转 180 度，适配倒装屏幕；正常安装时改为 `0`。此布局使用横屏方向 0 或 2。
- `REFRESH_INTERVAL_MS`：默认 200ms，约每秒 5 帧。
- `I2C_CLOCK_HZ`：默认 100000（100kHz），面包板/杜邦线接线优先使用标准速率。
- `CHUNK_BYTES`：每次主循环最多传输 16 字节图像；单次 I²C 等待上限配置为 5ms。

模块只接受主程序提交的最新状态快照，每帧完整发送后才重画下一帧，不排队积累旧状态。输入采样安排在显示传输之前。I²C 每块传输仍是同步调用；5ms 是采样目标周期，并非硬实时保证。

OLED 缺失、初始化失败或传输错误时，程序会禁用显示，继续采集输入和输出原有 14 通道串口数据，不在 FireWater 中混入错误文字。接好后按 RESET 重新探测。若屏幕不亮，依次检查额定供电、共地、SDA/SCL 接线、I²C 地址和实际屏幕驱动型号；`ControllerDisplay::available()` 可用于代码调试查看初始化/传输是否成功。

传输前检查 A4/A5 是否均为空闲高电平；若被拉低或发送失败，关闭显示总线及中断，复位后重新探测。此措施不能代替对供电、松动接线或短路的检查，也不能保证底层驱动在任何硬件故障下都能返回。

## 串口和 OLED 同时停止时的排查

两种 UNO R4 的串口实现不同，本程序按编译目标选择发送方式：

- **UNO R4 WiFi（默认核心配置）**：`Serial` 经 UART 桥接到 ESP32 的 USB 串口。该 UART 没有实现 `availableForWrite()`，返回 0 不能当作“不可发送”。程序在 115200 波特率下，每 1ms 最多发送 8 字节；正常发送一块约占用 0.7ms，不是完全异步发送。
- **UNO R4 Minima / 原生 USB 配置**：按 `availableForWrite()` 的实际空位发送，每次最多 32 字节；没有空位时立即返回。原生 USB 配置调用 `dtr()` 启用不依赖串口工具拉高 DTR 的兼容行为。

两种模式都先在内存生成完整一行，再由主循环分块发送。不要求底层缓冲区能一次容纳整行；已经发送一部分的帧保持不变，发完后再取下一帧。最多保留一帧，尚未开始发送时可替换为最新状态。堵塞恢复后可能先补完旧的一帧，随后恢复最新状态；不累积历史队列。切勿在 WiFi 的 UART 路径上用 `availableForWrite() == 0` 禁止发送。

**WiFi 版串口助手的波特率必须与代码一致，当前为 115200**。OLED 仍响应但串口无数据时，先检查选择的是开发板当前 COM 口、115200、8N1、无硬件流控；VOFA 使用 FireWater。如果只看原始文本，可先选 RawData。关闭其他占用同一 COM 口的软件后重新连接。

1. 若单按 RESET 无效，先拔掉 USB；若还有外接电源，也断开外接电源。断电后暂时断开 OLED 的四根线，再接 USB。
2. 若需要重新烧录但普通上传无效，快速按两次 RESET 进入引导模式；重新选择出现的 COM 口并上传。先关闭其他占用该端口的软件。
3. 在主程序将 `OLED_ENABLED` 改为 `false` 后编译上传。此配置完全跳过 I²C 初始化与刷新，只保留手柄采样和串口。反复推动摇杆，检查是否稳定。
4. 稳定后断电、接回 OLED，将 `OLED_ENABLED` 恢复为 `true` 并上传，再对比观察。默认显示速率已降低为 100kHz、5 帧/秒。
5. 若不接 OLED 仍异常，检查摇杆/按键在推动时是否拉动电源线、5V/GND 是否接触不良及 USB 线连接；记录 COM 口是否消失或重新枚举。

当前防护修复需要实机复测；串口和显示同时停止本身不能唯一确定故障来自 USB、I²C 或供电。

## VOFA 通道

每 50ms 发送一个带换行的 FireWater 数据帧。原有 0～9 通道顺序不变，新按键追加到末尾。

| 通道 | 内容 | 范围 |
| --- | --- | --- |
| 0 / 1 | 摇杆 1 处理后的 X / Y | -1000～1000，回中为 0 |
| 2 / 3 | 摇杆 2 处理后的 X / Y | -1000～1000，回中为 0 |
| 4 / 5 | 摇杆 1 / 2 的 L3 / R3 | 松开 0，按下 1 |
| 6 / 7 | 摇杆 1 原始 X / Y | 0～1023 |
| 8 / 9 | 摇杆 2 原始 X / Y | 0～1023 |
| 10 | 按键 A（D4） | 松开 0，按下 1 |
| 11 | 按键 B（D5） | 松开 0，按下 1 |
| 12 | 按键 X（D6） | 松开 0，按下 1 |
| 13 | 按键 Y（D7） | 松开 0，按下 1 |

将 10～13 通道绑定到单独的波形图，点击 Auto 调整纵轴，更容易观察 0/1 按键状态。按住时保持 1，松开后恢复 0。

如需人工可读文字，将 `.ino` 中的 `VOFA_OUTPUT` 改为 `false`，重新编译上传，再用串口监视器查看；此模式不用于 FireWater 绘图。

## 上板检查

- 分别按 A/B/X/Y，确认只有对应的 10/11/12/13 通道变为 1。
- 四键同时按住，应全部为 1；逐个松开，应分别回到 0。
- 按键时同时推动两个摇杆，检查摇杆通道仍正常响应。
- 松手时摇杆处理值为 0，所有按键状态为 0。
- 分别按下 L3/R3，确认 VOFA 的 4/5 通道与 OLED 的 L3/R3 标签一致。
- 左右摇杆圆点回中，满推时圆点与 ±1000 文本不越界；六键同时按住时六个标签反白。
- 同时操作输入、观察 OLED 并连接 VOFA，确认都正常响应。
- 不接 OLED 时重启，串口仍应正常；重新接好 OLED 后复位，应恢复显示。
